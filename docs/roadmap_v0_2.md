# Proposed v0.2: a temporary operating compact

**Status: proposal only.** The mechanics, transport system, and experiments below are not implemented. The four-season v0.1 engine and its completed records remain frozen.

The next question is whether a model can carry an understanding forward when its earlier intervention changes both the meaning of later evidence and the conditions under which it may act. The proposed extension joins those consequences in one temporary operating arrangement.

## Why this extension

The [independent Pro review](../reviews/pro_review_v0_1.md), prepared without inspecting the Astra results, identified two structural limits: ordinary play scarcely exposes masking, and construction makes reuse optimal for every remaining season under the default charter. The [pilot summary](../experiments/astra_v0_1/summary.json) is consistent with that diagnosis: all 32 game decisions were optimal, but every game built in season 1 and then reused; no full game encountered a masked surface observation.

This supports improving the task's coverage and sustained dependencies. It does not establish a model ranking. Adding seasons alone would extend the easy continuation unless a later event changes the value or permissibility of using the asset.

## 1. First, automate exact packet delivery

Before another model comparison, build a transport layer that sends the engine's serialized public packet directly to the contestant. Retain the exact submitted input and raw returned output before parsing, alongside the parsed response, applied action, validation result, and a digest of each record. Record any fallback without replacing the original response. Generate the public rules/configuration manifest from the referee's configuration, including prior, horizon, charter, and observation likelihoods; identify that manifest in every packet.

This is a proposed engineering correction to an observed problem. In v0.1, manual delivery changed punctuation in C1 and one historical expenditure in B2. Canonical replay cannot establish byte-exact input identity, and B2 is not a clean replication. Both discrepancies remain in the [deviation record](../experiments/astra_v0_1/protocol_deviations.json).

The proposed runner should enforce separation between contestants, private world state, and evaluator outputs. The pilot used instructions, not hardened isolation. Record model identity, settings, inference time, tokens, and cost only when exposed by the interface. Keep game credits, response limits, and monetary budgets distinct; mark unavailable telemetry explicitly.

## 2. Make the operating arrangement temporary

These mechanics develop the review's [temporary operating compact](../reviews/pro_review_v0_1.md). Numerical settings require calibration before comparison.

### Monitoring that persists

An emergency buffer installation would move a named sensor from the source to a treated-water store. Its readings would remain weakly informative or uninformative about the source until a crew restores source sampling. A monitoring configuration would persist across decisions; it would no longer depend only on the immediately preceding operation.

Public likelihoods and accessible installation/restoration history would support inference from each named sensor. A separate condition would supply the monitoring configuration explicitly, distinguishing reconstruction from history from planning with that state already supplied.

### Information that arrives after a delay

A source assay would consume credits and a work slot, returning after a declared number of operating decisions. A pending-investigation ledger would retain its target, sampling time, and due time. Investment or renewal would have a fixed deadline.

Some situations should reward ordering an assay before its importance becomes immediate. Others should make it unnecessary or too late. Delays and deadlines would be fixed by the scenario rules, never invented after seeing a model's choice. Initially, the hidden source condition would remain fixed to keep inference inspectable.

### An asset whose permission can expire

Construction would create a durable works asset; operation would also require a temporary access compact. One candidate grants two uses, each consuming a permission. Renewal would require a work slot and a declared payment or compensating action. An obligation ledger would record the affected participant, accepted burden, promised remedy, and due condition.

The asset could therefore survive while its authority to operate expires. A subsequent shortage would require renewal, replacement, or a specified exceptional procedure. Physically possible but unauthorised use should be represented distinctly from physical impossibility, so a breach can be observed and scored under the declared mandate.

### A small candidate campaign

Start by investigating **six seasons and two public charters**. One charter could require renewed permission; another could allow a narrowly defined emergency exception with an enforceable remedy. Their procedures and consequences would be public. Two uses, six seasons, and the charter pair are starting hypotheses, not validated design choices or moral standards.

The candidate state would add monitoring configuration, pending investigations, remaining permission, and outstanding obligations to v0.1's resources, asset, and debt. Participant-level consequences should remain visible alongside charter loss. Exact reference planning is desirable while the state space permits it; any approximation must be disclosed. A separate deliberation track would be needed for questions a charter leaves unresolved.

## 3. Establish exposure before comparing models

For every claimed mechanism, the proposed scenario audit would record whether a relevant decision occurs, whether a targeted error changes a feasible continuation, and the resulting expected loss gap. It would also check whether a simple policy already solves the case. A tiny gap remains a weak decision discriminator even when belief reconstruction is revealing.

| Targeted control | Matched counterpart to include |
| --- | --- |
| Ignore a persistent monitoring change | A restored source sensor really is informative |
| Treat a delayed assay as immediately available | An early assay arrives in time; another inquiry is wasteful |
| Forget expiry or an outstanding remedy | Permission remains valid, or renewal is feasible and worthwhile |
| Always preserve the initial arrangement | Some worlds favour renewal; others favour replacement |

Generate and freeze coverage-balanced scenarios using these controls before inspecting candidate model rankings. Count observations once per actual history, keep supplied checkpoints separate from complete campaigns, and preserve all tied optimal actions. Predeclare posterior reconstruction error alongside realised Brier score where an exact public-information posterior exists. The [review](../reviews/pro_review_v0_1.md) explains why these measure different things.

## 4. Test the sustained-understanding hypothesis

The proposed comparison would pair connected campaigns with matched independent cases, and full accessible histories with supplied sufficient-state summaries. These contrasts would investigate whether an advantage comes from retaining causal and relational consequences, reconstructing state, or planning once the state is explicit. Matching difficulty is itself a design task, not an assumed guarantee.

Use multiple charters, independent world families, and repeated runs selected by a declared sampling plan. Separate tools-allowed and tools-restricted conditions; a permitted solver is a legitimate strategy. Report available compute and cost measures without treating response count as a dollar budget. Choose replication counts from a pilot variance estimate and a minimum relevant effect, rather than counting successive turns as independent experiments.

## Proposed milestones and version boundary

1. Add exact transport, raw provenance, configuration manifests, and explicit isolation/telemetry reporting.
2. Implement and inspect the compact's transitions and reference planner in a new version, preserving v0.1.
3. Audit mechanism exposure, ablation gaps, simple-policy performance, and sensitivity to cutoff liabilities and asset value.
4. Freeze engine, rules, charters, world-selection procedure, scoring, model settings, and budgets before comparison. Keep confirmatory worlds separate until evaluation ends; release demonstration seeds after use.

The intended advance is a repeated dependency: an early remedy changes later observation, access, and obligation. Its ability to discriminate sustained reasoning remains an empirical question.
